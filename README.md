# PowerMatch Telegram Bot

ربات تلگرام PowerMatch برای **جمع‌آوری** عرضه و تقاضای برق بر پایه‌ی تقویم شمسی.

> 🔒 این ربات اطلاعات را فقط جمع‌آوری می‌کند. هیچ داده‌ای از یک کاربر به کاربر دیگر
> (با هر نقشی) نمایش داده نمی‌شود؛ تنها ادمین‌ها دسترسی کامل دارند.

قابلیت‌ها:
- پیام معرفی هنگام اولین `/start` و دستور `/about` (متنش از داخل تلگرام قابل ویرایش است)
- ثبت‌نام سازمانی: نیروگاه، خریدار نهایی/صنعت، خرده‌فروش، کارگزاری
- چند سازمان/نقش برای یک کاربر تلگرام + سوییچ «پروفایل فعال» با دکمه
- ثبت عرضه (فروش) و تقاضا (خرید) با انتخاب دکمه‌ای دوره‌ی تحویل شمسی (هفتگی/ماهانه)
- **واحدها: حجم بر حسب کیلووات (kW) و قیمت بر حسب ریال**
- شماره‌ی سفارش مستقل برای هر پروفایل کاربر
- نوتیف لحظه‌ای برای ادمین + خروجی اکسل و Google Sheets

## اجرا
1. Python 3.11+
2. `pip install -r requirements.txt`
3. `.env.example` را به `.env` تبدیل و مقادیر را پر کنید.
4. `python -m app.main`

## متغیرهای محیطی
| کلید | توضیح |
|---|---|
| `TELEGRAM_BOT_TOKEN` | توکن ربات |
| `DB_PATH` | مسیر فایل SQLite |
| `ADMIN_SECRET` | هدر `X-Admin-Secret` برای API. اگر خالی/`change-me` باشد، `/admin/*` با ۵۰۳ غیرفعال می‌شود |
| `BOT_USERNAME` | یوزرنیم ربات برای لینک «معرفی به همکاران» (اختیاری) |
| `ADMIN_USERNAMES` | یوزرنیم ادمین‌ها بدون @، جداشده با کاما |
| `ADMIN_CHAT_IDS` | شناسه‌های عددی چت ادمین‌ها |
| `API_HOST` / `API_PORT` | پیش‌فرض `127.0.0.1:8000` |
| `GOOGLE_CREDENTIALS_FILE` / `GOOGLE_SHEET_ID` | اختیاری، برای همگام‌سازی گوگل‌شیت |
| `TURSO_DATABASE_URL` / `TURSO_AUTH_TOKEN` | اختیاری؛ اگر پر شود، دیتابیس به‌جای فایل محلی روی Turso (libSQL) نگه‌داری می‌شود |

## استقرار روی سرور
راهنمای کامل در [deploy/README.md](deploy/README.md) — خلاصه: BotFather میزبانی نمی‌کند،
به یک VPS نیاز دارید. اسکریپت آماده: `bash deploy/setup_server.sh`.

## استقرار بدون سرور (GitHub Actions)
`.github/workflows/bot.yml` بات را بدون هیچ VPS/سروری، رایگان روی GitHub Actions اجرا
می‌کند: هر ۵ دقیقه یک اجرای جدید صف می‌شود اما `concurrency` تضمین می‌کند فقط یکی هم‌زمان
در حال polling باشد؛ هر اجرا تا نزدیک سقف ۶ ساعتی Actions زنده می‌ماند و بعد اجرای بعدی
از صف ادامه می‌دهد — یعنی بات تقریباً ۲۴/۷ کار می‌کند.

چون runner بین اجراها پاک می‌شود، فایل SQLite محلی نمی‌تواند دیتابیس اصلی باشد؛ باید
`TURSO_DATABASE_URL` و `TURSO_AUTH_TOKEN` تنظیم شوند تا `db.py` به‌جای فایل محلی از
[Turso](https://turso.tech) (سرویس رایگان libSQL) استفاده کند. راه‌اندازی:

```
turso auth login
turso db create powermatch
turso db show powermatch --url
turso db tokens create powermatch
```

سپس در ریپوی گیت‌هاب (خصوصی)، زیر Settings → Secrets and variables → Actions این
مقادیر را اضافه کنید: `TELEGRAM_BOT_TOKEN`, `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` و
هر کدام از بقیه‌ی متغیرهای بالا که نیاز دارید (برای Google Sheets، محتوای فایل JSON را
در سیکرت `GOOGLE_CREDENTIALS_JSON` بگذارید). با `workflow_dispatch` هم می‌توانید بات را
دستی از تب Actions اجرا کنید.

## پنل ادمین — فضای اختصاصی
پنل مدیریت از فضای کاربری جداست:

- **حالت پیش‌فرض:** `/admin` در همان ربات، «حالت مدیریت» را با کیبورد کاملاً متفاوت
  باز می‌کند (دکمه‌های کاربری دیده نمی‌شوند). با «🚪 خروج از پنل» یا `/start` برمی‌گردید.
- **جداسازی کامل:** اگر `ADMIN_BOT_TOKEN` را در `.env` پر کنید، پنل و همه‌ی گزارش‌های
  لحظه‌ای به یک **ربات دوم و مستقل** منتقل می‌شوند و هیچ‌گاه با چت کاربران قاطی نمی‌شوند.

`/admin` همه‌ی تنظیمات زیر را بدون تغییر کد پوشش می‌دهد:

| دکمه / دستور | کار |
|---|---|
| 📊 `/report` | فایل اکسل کل داده‌ها |
| 📄 `/sheet` | همگام‌سازی گوگل‌شیت (یا نمایش دقیق آنچه کم است) |
| ℹ️ `/setabout` | ویرایش متن «درباره ما» |
| 🔔 روشن/خاموش | فعال‌سازی یادآوری روزانه |
| ⏰ ساعت‌های ارسال | مثلاً `09:30,11:00` به‌وقت تهران |
| ✍️ متن یادآوری | با متغیرهای `{name}`, `{role}`, `{periods}` |
| 👥 مخاطبان | همه، یا فقط نقش‌های انتخابی (نیروگاه/خریدار/خرده‌فروش/کارگزاری) |
| 🚀 ارسال آزمایشی | ارسال فوری بدون انتظار تا ساعت مقرر |
| 📈 `/stats` | آمار کلی |

### یادآوری روزانه
هر روز در ساعت‌های تنظیم‌شده، به پروفایل‌هایی که برای **نزدیک‌ترین دوره‌ی هفتگی و ماهانه**
هنوز حجم و قیمت ثبت نکرده‌اند پیام یادآوری ارسال می‌شود. هر کاربر در هر نوبت فقط یک‌بار
پیام می‌گیرد (جدول `reminder_log`).

## ویرایش و حذف — ردپای تغییرات
کاربر می‌تواند پروفایل و سفارش‌های خود را ویرایش یا حذف کند، اما **هیچ رکوردی از گزارش
حذف نمی‌شود**: حذف نرم است و ستون‌های «وضعیت»، «تاریخ حذف»، «آخرین ویرایش» و
«تاریخچه تغییرات» در اکسل، به‌همراه شیت مستقل «تاریخچه تغییرات»، همه‌ی تغییرات را با
تاریخ و ساعت شمسی نگه می‌دارند.

ادمین با **یوزرنیم** شناخته می‌شود؛ برای دریافت نوتیف لحظه‌ای باید یک‌بار خودش
`/start` را در ربات بزند تا `chat_id` او ثبت شود (تلگرام اجازه‌ی ارسال پیام با
یوزرنیم را به ربات‌ها نمی‌دهد).

## اتصال به Google Sheets
1. در `console.cloud.google.com` پروژه بسازید و **Google Sheets API** را Enable کنید.
2. یک **Service Account** بسازید و کلید JSON آن را دانلود کنید.
3. یک Google Sheet بسازید و آن را با ایمیل `client_email` داخل آن JSON، با دسترسی **Editor** به اشتراک بگذارید.
4. در `.env` مقادیر `GOOGLE_CREDENTIALS_FILE` و `GOOGLE_SHEET_ID` را پر کنید.
5. `pip install gspread google-auth` و سپس `/sheet` در ربات.

پس از تنظیم، شیت **لحظه‌ای** به‌روزرسانی می‌شود: با هر ثبت/ویرایش/حذف، همگام‌سازی در
پس‌زمینه اجرا می‌شود. برای عیب‌یابی:

```
python -m app.gsheet
```

این دستور دقیقاً می‌گوید کدام قطعه کم است (کتابخانه، فایل کلید، شناسه‌ی شیت، یا دسترسی Editor).

## کد دوره‌ها
- **ماهانه:** `YYYYMM01` (مثال `14050601` = شهریور ۱۴۰۵)
- **هفتگی:** تاریخ شمسی شنبه‌ی همان هفته، `YYYYMMDD`

مهلت ثبت هر هفته، روز `weekly_cutoff_weekday` (پیش‌فرض سه‌شنبه) در هفته‌ی پیش از آن است؛
برای ماه، آخرین `monthly_cutoff_weekday` پیش از شروع ماه. مقادیر از جدول
`market_calendar_rules` خوانده می‌شوند و با `PUT /admin/calendar` قابل تغییرند.

## API
همه‌ی `/admin/*` نیازمند هدر `X-Admin-Secret` هستند.
- `GET /health`
- `GET /admin/organizations` · `GET /admin/offers` · `GET /admin/requests` · `GET /admin/matches`
- `GET /admin/calendar` · `PUT /admin/calendar`
- `GET /admin/export`
