# استقرار روی سرور

## پاسخ کوتاه: آیا BotFather می‌تواند ربات را میزبانی کند؟
**خیر.** BotFather فقط ربات را *ثبت* می‌کند و به شما توکن می‌دهد. کدِ ربات باید روی یک
کامپیوتر همیشه‌روشن اجرا شود. تا وقتی ربات روی لپ‌تاپ شما اجرا می‌شود، با خاموش شدن
سیستم یا قطع اینترنت، ربات هم از دسترس خارج می‌شود.

پس یکی از این گزینه‌ها لازم است:

| گزینه | هزینه | مناسب برای |
|---|---|---|
| **VPS ایرانی** (آروان، ابرآسیا، پارس‌پک…) | ~۱۵۰–۴۰۰ هزار تومان/ماه | ✅ **پیشنهاد ما** — بدون تحریم، پینگ کم، پرداخت ریالی |
| VPS خارجی (Hetzner، Contabo…) | ~۴ یورو/ماه | نیاز به کارت ارزی؛ برخی IPها برای API تلگرام مشکل ندارند ولی برای گوگل ممکن است |
| Railway / Render / Fly.io | پلن رایگان محدود | تست سریع؛ پلن رایگان معمولاً ربات را می‌خواباند |
| کامپیوتر خودتان + اینترنت دائم | رایگان | فقط برای تست |

کمترین مشخصات کافی است: **۱ هسته CPU، ۱ گیگ رم، ۱۰ گیگ دیسک، اوبونتو ۲۲/۲۴**.

## روش ۱ — نصب مستقیم روی VPS (پیشنهادی)

```bash
# روی سیستم خودتان: آپلود پروژه
scp -r d:/Desktop/powermatch_bot_mvp root@SERVER_IP:/opt/powermatch

# روی سرور
ssh root@SERVER_IP
cd /opt/powermatch
nano .env            # توکن، ADMIN_USERNAMES، ADMIN_SECRET و... را پر کنید
bash deploy/setup_server.sh
```

اسکریپت همه‌چیز را انجام می‌دهد: پایتون، محیط مجازی، کتابخانه‌ها، منطقه‌ی زمانی تهران،
سرویس systemd با ری‌استارت خودکار.

دستورهای روزمره:
```bash
systemctl status powermatch      # وضعیت
systemctl restart powermatch     # ری‌استارت بعد از تغییر .env
journalctl -u powermatch -f      # لاگ زنده
```

به‌روزرسانی کد:
```bash
scp -r app root@SERVER_IP:/opt/powermatch/     # یا git pull
ssh root@SERVER_IP systemctl restart powermatch
```

## آیا می‌شود «بدون سرور» (serverless) اجرا کرد؟
راهنمای رسمی تلگرام در `core.telegram.org/bots/serverless` اجرای ربات روی سکوهای
serverless (مثل Cloudflare Workers) را با **وب‌هوک** توضیح می‌دهد. برای رباتی که
یک تابع کوچک و بی‌حالت است عالی است، ولی این پروژه چهار چیز دارد که با مدل serverless
جور درنمی‌آید:

| نیاز این ربات | مشکل در serverless | جایگزین لازم |
|---|---|---|
| دیتابیس SQLite روی دیسک | فایل‌سیستم موقتی است و بین اجراها پاک می‌شود | Postgres/D1/Turso + بازنویسی لایه‌ی داده |
| یادآوری ساعت ۹:۳۰ و ۱۱ | تابع serverless دائم اجرا نمی‌شود | Cron Trigger جدا |
| ساخت فایل اکسل با openpyxl | محدودیت حافظه/زمان اجرا | سرویس جدا |
| پایتون + aiogram + gspread | Workers جاوااسکریپت‌محور است؛ پشتیبانی پایتون محدود است | بازنویسی کامل |

**نتیجه:** برای این پروژه صرف نمی‌کند؛ عملاً یعنی بازنویسی از صفر برای صرفه‌جویی در
هزینه‌ای که ماهانه چند صد هزار تومان است. یک VPS ساده هم ارزان‌تر تمام می‌شود هم
سریع‌تر راه می‌افتد.

**اما** چیزی که از آن راهنما به‌درد می‌خورد پیاده شد: **حالت وب‌هوک**. با آن، به‌جای
long polling، تلگرام آپدیت‌ها را به سرور شما POST می‌کند — پایدارتر پشت nginx و
پیش‌نیاز هر استقرار ابری:

```bash
# در .env
USE_WEBHOOK=1
WEBHOOK_BASE_URL=https://bot.example.com     # باید HTTPS معتبر باشد
WEBHOOK_SECRET=$(python -c "import secrets;print(secrets.token_urlsafe(32))")
API_HOST=0.0.0.0
```
سپس `python -m app.main`. ربات خودش آدرس وب‌هوک را در تلگرام ثبت می‌کند
(`/telegram/webhook` و برای ربات ادمین `/telegram/webhook/admin`) و هدر مخفی را
بررسی می‌کند تا کسی نتواند آپدیت جعلی بفرستد. برای HTTPS معتبر، nginx + certbot کافی است.
اگر `USE_WEBHOOK` خالی باشد، همان long polling قبلی اجرا می‌شود.

## روش ۲ — داکر

```bash
cd /opt/powermatch
docker compose up -d --build
docker compose logs -f
```
`docker-compose.yml` پورت API را فقط روی `127.0.0.1` منتشر می‌کند و دیتابیس در
`./data` بیرون از کانتینر می‌ماند.

## نکته‌های مهم

1. **فایل‌های حساس را جا نگذارید:** `.env` و `google_credentials.json` باید روی سرور
   باشند ولی هرگز داخل گیت نروند (در `.gitignore` هستند). روی سرور `chmod 600` شوند.
2. **دیتابیس:** `powermatch.db` را از سیستم خودتان به سرور کپی کنید تا داده‌های فعلی
   حفظ شود. بکاپ ساده:
   ```bash
   0 3 * * * cp /opt/powermatch/powermatch.db /opt/powermatch/backup/db-$(date +\%F).db
   ```
3. **فقط یک نسخه هم‌زمان اجرا شود.** اگر ربات روی لپ‌تاپ و سرور هم‌زمان اجرا شود،
   تلگرام خطای `terminated by other getUpdates` می‌دهد. اول لوکال را ببندید.
4. **ساعت سرور:** یادآوری‌ها با ساعت تهران کار می‌کنند؛ اسکریپت این را تنظیم می‌کند.
5. **API مدیریتی** پیش‌فرض روی `127.0.0.1` است. اگر از بیرون لازمش دارید، پشت nginx با
   HTTPS بگذارید — نه مستقیم روی اینترنت.
